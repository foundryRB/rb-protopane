**Date**: 2026-07-04
**Status**: Decided

## Context

The instance is internet-exposed and holds client prototypes: names, branding, and unreleased product surfaces. Access control must be enforced by the application itself, not only at the network edge, and a misconfigured deployment must never be silently public.

## Decision

An application-level middleware gates every route behind HTTP Basic auth. With `PROTOPANE_AUTH_USER`/`PROTOPANE_AUTH_PASSWORD` set, requests without valid credentials answer 401. With neither set and auth not explicitly disabled, protected routes answer 503: closed, never open. `/api/health` stays exempt so orchestration probes work. The middleware runs before routing, so mounted sub-applications (the SPA catch-all, `/mcp`) are covered by the same gate.

## Rationale

- Fail-closed turns the most dangerous misconfiguration (forgotten Secret) into an outage instead of a leak.
- One credential story for every door keeps trust calibration in one place; MCP clients pass the same header at connect time.
- Basic auth over TLS is sufficient for a single-operator tool; per-user identity would be machinery without a requirement.

## Alternatives considered and rejected

- **Edge-only auth (tunnel or gateway policy)**: leaves the app naked against any internal path or misrouted Ingress, and couples correctness to infrastructure the app cannot test.
- **OIDC/session login**: right when there are users to distinguish; here it adds a provider dependency and a login UI for exactly one operator.
