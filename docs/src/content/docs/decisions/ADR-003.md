**Date**: 2026-07-04
**Status**: Decided

## Context

Screens are HTML bodies in Tailwind utility classes backed by shadcn design tokens. The GrapesJS canvas is an iframe that must render arbitrary dropped markup fully styled, retheme live as tokens change, and keep working in a design session with no internet (customer sites, demo rooms).

## Decision

The canvas iframe loads three local assets: a vendored Tailwind Play runtime (`/vendor/tailwind-play.js`), a config mapping the shadcn utility names to `hsl(var(--token))` CSS variables (`/canvas/tw-config.js`), and a token stylesheet with the `:root` defaults (`/canvas/theme.css`). The theme panel drives tokens by setting CSS variables on the canvas document, so every utility class resolves live. Typography follows the same path: the `--font-sans` token is a system font stack, so no webfont loading is ever needed.

## Rationale

- Arbitrary markup needs a runtime utility compiler; a prebuilt CSS file would only cover classes seen at build time.
- Self-hosting removes the CDN dependency: the canvas renders identically offline and behind strict egress.
- Tokens as CSS variables give live retheming for free (change one variable, every surface follows) and export unchanged into a real frontend's theme layer.

## Alternatives considered and rejected

- **Tailwind Play CDN**: identical capability, but the canvas goes unstyled exactly when it matters (offline session, blocked CDN).
- **Prebuilt utility CSS with safelisting**: either a megabyte-scale safelist-everything build or silent gaps when a screen uses a class the build never saw.
- **Webfont-based typography presets**: better variety, but reintroduces network dependence and licensing; system stacks keep the offline guarantee.
